# Mid-Sprint Project: Notes App with Collections and Search
## Систематизированные требования (цель — максимальный балл)

> Формат проекта: mid-sprint, без peer/expert review. Ты сама проходишь Review-чеклист, пишешь `REFLECTION.md` и двигаешься дальше. Приложение работает только локально (`npm run dev`), без деплоя и авторизации — они позже в спринте.

---

## 1. Суть проекта

Notes-приложение с нуля, где Supabase — слой хранения с самого начала:

- **Sidebar с коллекциями** — именованные группы заметок (раскрывающиеся).
- **Система тегов** — сквозные метки поверх коллекций (many-to-many).
- **Поиск** — фильтрует по заголовкам и тексту всех заметок сразу.

Твоя роль: спроектировать таблицы в дашборде Supabase, написать бриф, держать агента в рамках через `CLAUDE.md` и ревьюить диффы перед merge. Код пишет агент (Claude Code).

## 3. Схема базы данных (создаётся в Supabase Dashboard → Table Editor)

Порядок создания важен (из-за FK): **collections → notes → tags → note_tags**.

### collections
| Колонка | Тип | Примечание |
|---|---|---|
| id | int | PK |
| name | string | |
| created_at | timestamp | |

### notes
| Колонка | Тип | Примечание |
|---|---|---|
| id | int | PK |
| title | string | |
| body | string | |
| collection_id | int, FK → collections.id | **nullable** — заметка может быть вне коллекций |
| created_at | timestamp | |
| updated_at | timestamp | |

### tags
| Колонка | Тип | Примечание |
|---|---|---|
| id | int | PK |
| name | string | |

### note_tags (join-таблица)
| Колонка | Тип | Примечание |
|---|---|---|
| note_id | int, FK → notes.id | |
| tag_id | int, FK → tags.id | |

Связи простым языком (так и формулировать в промптах!):
- Заметка может принадлежать одной коллекции; коллекция содержит много заметок. Заметка может быть без коллекции.
- Заметка может иметь много тегов; тег может стоять на многих заметках — поэтому join-таблица `note_tags`.

## 4. Обязательные требования (все 12)

1. **Централизованный доступ к данным.** Все чтения/записи — через `supabase-js`, собранные в одном helper-модуле (напр. `app/lib/db.ts`). Никаких запросов, разбросанных по компонентам.
2. **Таблица `notes`** минимум с: `id`, `title`, `body`, `created_at`, `updated_at`.
3. **Таблица `collections`** с: `id`, `name`, `created_at`.
4. **Заметка ↔ коллекция.** `notes.collection_id` → `collections.id`, nullable.
5. **Теги через join-таблицу.** `tags` + `note_tags` (одна строка = одна связь заметка–тег).
6. **Sidebar: раскрывающиеся коллекции.** Клик раскрывает заметки внутри. Заметки без коллекции — в группе "All notes" / "Uncollected".
7. **New collection** из sidebar: запрашивает имя, добавляет сразу.
8. **Назначение коллекции** из карточки заметки (dropdown/picker), сохраняется в БД.
9. **Добавление/удаление тегов** на заметке; теги видны на карточке в sidebar.
10. **Тег-фильтр в sidebar** — логика **AND**: показывать только заметки, у которых есть **каждый** из выбранных тегов (не "любой из"!). ⚠️ Самое частое место ошибки агента — формулировать в промпте явно.
11. **Поиск** сверху воркспейса: по title + body, обновляется по мере ввода, **учитывает активный тег-фильтр**.
12. **Empty states** везде: пустая коллекция, нет результатов поиска, нет совпадений по тегам — никаких пустых экранов.

## 5. Опциональные задачи

Минимум **одна** через отдельную ветку + PR. Для максимума — **две** (вторая = бонус, объяснить в REFLECTION.md).

**Easy:**
- Rename коллекции (inline edit, персистится).
- Цветные теги (палитра, цветная точка/pill на карточках и в фильтре).
- Счётчик заметок на коллекции (обновляется при добавлении/перемещении).
- **Кастомный code-review skill / `/code-review` команда** (через skill-creator): ревьюит PR-дифф против правил CLAUDE.md — обход централизованного слоя данных, несовпадение полей со схемой и т.п. Запустить хотя бы на одном PR, вывод — в REFLECTION.md.

**Medium:**
- Перемещение заметок между коллекциями (drag-and-drop или контекстное меню).
- Pinned notes (boolean-колонка в `notes`, закреплённые — вверху коллекции).
- Архив (archive/unarchive, секция "Archive" в sidebar).

**Hard:**
- Серверный full-text search (встроенный FTS Supabase + индекс; поведение для пользователя не меняется).
- Шаринг коллекции по read-only ссылке (share token в `collections`).
- История поиска (последние 5 запросов в БД, подсказки под инпутом).

## 9. Рекомендованный порядок работы

1. **Подготовка:** Supabase-проект → 4 таблицы в Table Editor (collections → notes → tags → note_tags, FK через встроенный picker) → скопировать структуру в `docs/supabase-schema.md`.
2. **CLAUDE.md** до кода: откуда credentials (env), какой модуль владеет доступом к данным (`app/lib/db.ts`), конвенции для каждой новой фичи.
3. **Сборка по кускам** (коммит на каждом стабильном состоянии):
   scaffold + notes CRUD *(самый рискованный этап — заложить больше времени)* → collections UI → теги → поиск → опциональная задача №1 → опциональная №2.
4. **Для каждой Supabase-фичи** — паттерн *search → paste → cite*: найти раздел доков supabase-js, вставить сниппет в промпт, указать URL.
5. **Каждая фича** = ветка + PR: сторонняя slash-команда на диффе (+ своя `/code-review`, если взята) → fresh-session review хотя бы раз → merge.
6. **REFLECTION.md** по ходу: находки команд, проблемы scaffold-этапа, объяснение второй опциональной задачи.
